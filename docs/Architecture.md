# Architecture - New College Course Navigator

**Author:** Jaxon
**Date:** November 2, 2026
**Status:** Describes the working prototype at `C:\dev\course-navigator`, plus the decisions
that bind work not yet built.

> This document describes a system that largely exists. Where a section describes something not
> yet implemented it says so in the heading. BMAD's epic planning should treat the "Not yet
> built" items as the source of implementation work and the rest as constraints on it.

---

## 1. Context

A server-rendered web application over a read-only snapshot of one term's course catalog, plus
a small amount of per-student state. There is no multi-tenancy, no external customer, and no
scale problem: roughly 250 students and 10 advisors at one institution.

The architecture is shaped by three constraints that are not negotiable:

1. **Grounding is structural, not behavioural.** The model is handed real section identifiers
   and may only reorder them; the validity of output is checked in code, not requested in a
   prompt (**D-16**, **F-26**). This drives the two-stage ranker in §6.
2. **The product must run with no network and no credential.** A graded demonstration cannot
   depend on a round trip, so every AI path has a deterministic fallback (**NFR4**, **NFR5**).
3. **Requirement rules are auditable.** Rules are data in tables, not code branches, so a tag
   can be explained and a rule set can be versioned by catalog year (**NFR7**, **NFR9**).

### Starter template

**None.** This is not a greenfield scaffold from a template — it is an existing Python
application. Epic 1 Story 1 should **not** be a project-initialisation story. The repository
is initialised, dependencies are declared in `requirements.txt`, and the application runs.

## 2. Stack

| Layer | Choice | Why |
|---|---|---|
| Language | Python 3 | The Banner scraper it feeds on is already Python |
| Web | Flask, server-rendered Jinja | No build step, no npm, no client framework |
| Store | SQLite (`navigator.db`), WAL | Single file, zero setup, survives being emailed |
| Retrieval | Pure-Python TF-IDF (`rank.py`) | No numpy, no service. Flask is the only hard dependency. |
| Rerank | `anthropic` 2.4.0, `claude-opus-5` default | Optional. Absent credential degrades, never breaks. |
| Auth | **None** | Deliberate — see §9 |
| Deployment | **None** — `python app.py`, localhost:5000 | Deliberate — see §9 |

The dependency list is deliberately near-empty. The one optional dependency is the Anthropic
SDK, and the application imports it defensively.

## 3. Data model

`schema.sql` plus `reference_data.sql`. Every table names the decision it implements. 14 tables
in four groups.

| Group | Tables |
|---|---|
| People | `advisor`, `student`, `app_user` |
| Rules | `gen_ed_bucket`, `requirement`, `requirement_bucket` |
| Catalog | `course`, `course_offering`, `offering_attribute` |
| Student state | `completed_course`, `completed_course_bucket` |
| Search | `search_request`, `recommendation`, `recommendation_bucket` |

> **Catalog measurements cited in this document are canonical in**
> [`reference/new-college-requirements.md`](../reference/new-college-requirements.md) **§11.**
> Figures are restated here only where they justify a schema decision. If one changes, change
> it there first.

### The three load-bearing modelling decisions

**Requirements are a union of buckets, not a hierarchy (D-28).** A `requirement` joins to many
`gen_ed_bucket` rows through `requirement_bucket`. Measured on `spring2027.csv`, nesting would
be wrong: Literature co-tags Humanities 95% of the time and World Language 93%, but Fine Arts
only 10% and History / Social-and-Behavioral **0%**. Modelling Literature as a child of
Humanities would silently drop the 5% that are not, and the checklist's "including at least one
Literature" clause has nowhere to live. It is carried as
`requirement_bucket.is_must_include`.

Encoded today: **13 requirements** over a **12-attribute allowlist**. The other 14 Banner
attributes never produce a requirement tag.

**Lab is not an attribute.** No Banner attribute anywhere contains "lab". The 2-hour lab rule
inside the 8-hour Natural Science requirement is satisfied from
`course_offering.schedule_type = 'Laboratory'` (296 sections). `requirement.lab_hours_needed`
carries it as a separate column rather than a bucket.

**`recommendation.offering_id` is NOT NULL.** Every recommendation points at a real section.
This resolves a conflict between the v1 ERD and the process diagram, in favour of the ERD,
which is also what **D-16** requires. A recommendation that is not a real offered section is
not representable.

### Cut from ERD v1

`topic`, `course_topic`, `career`, `career_topic`, `search_request.career_id` — a hard-coded
taxonomy, which **D-22** forbids. Replaced by `course.description` ranked against a typed
phrase.

### A correctness trap the schema cannot prevent

A course can carry two buckets belonging to the **same** requirement — SPA 101 is both World
Language and Humanities — so a naive `SUM` over the join counts its credits twice and
overstates progress. `db.outstanding_buckets` sums over `DISTINCT completed_id`. Getting this
wrong marks a requirement satisfied and hides a course the student still needs, which is
exactly the failure the product exists to prevent (**F-12**, **NFR8**).

## 4. Data sources and ingestion

| Source | Mechanism | Volume |
|---|---|---|
| Banner 9 section data | `C:\dev\ua-classes\ua_classes.py`, JSON, no login | 9,621 sections / 3,324 courses, term 202710 |
| Course descriptions | `POST /searchResults/getCourseDescription` | 3,172 cached; ~5% return HTTP 500, meaning no record exists |
| Requirement rules | Hand-encoded in `reference_data.sql` | 13 requirements, 12 buckets |
| Seminar themes (**not yet built**) | `reference/nc-seminar-themes-202710.csv`, extracted from the term course booklet | 15 seminars, 12 tagged |
| Completed coursework | Seeded by `seed.py` | 1 advisor, 3 students (**D-24**) |

Setup is a four-step pipeline, each step idempotent:

```
python ingest.py --reset      # build navigator.db, load the term
python seed.py                # demo advisor + 3 students
python descriptions.py        # cache descriptions, ~25 min, resumable
python app.py                 # http://127.0.0.1:5000
```

`descriptions.py` only fetches courses whose description is still empty, so re-running it
retries failures. Descriptions are **course-level, not section-level** — every `AAST 395`
section returns the same blurb — so they are fetched once per subject and number.

### Two ingestion defects, fixed, not to be reintroduced

**HTML entities must be unescaped before attribute splitting.** Banner returns escaped text.
`&amp;` ends in a semicolon and the attribute column joins on `"; "`, so
`PW: Digital Literacy & Pract` split into two bogus attributes. Fixed at source in
`ua_classes.py` with `unesc()`; also affected `title` (**581** rows), `building`, `sectionText`
and `instructors`. `ingest.py` unescapes defensively on read because CSVs on disk still carry
the broken values.

**WAL must be set at creation.** Journal mode cannot be switched from an ordinary connection,
so a `database is locked` error appeared on any search during a description fetch. WAL plus
`busy_timeout` is set when the database is created (**NFR6**).

## 5. Application structure

```
app.py          4 routes, no blueprints
db.py           connection, schema creation, all queries
ingest.py       Banner CSV -> SQLite, attribute mapping, topic flagging
descriptions.py resumable description fetch
rank.py         TF-IDF index, bucket scoring, combined ranking
rank_llm.py     optional second-stage rerank + validation
templates/      base, home, results, advisor
```

| Route | Role | Purpose |
|---|---|---|
| `/` | — | Role picker over `app_user` |
| `/student/<id>` | student | Outstanding requirements + phrase search |
| `/advisor/<id>` | advisor | Advisee list with outstanding counts |
| `/advisor/<id>/student/<id>` | advisor | The student view, on a student's behalf |

Both result views share one function, `_results_page`, so the student and the advisor see the
same ranking from the same code path. This matters for **FR29**: an advisor must see what the
student sees, and divergence would be a defect rather than a feature.

## 6. Ranking — the core AI feature

Two independent halves, deliberately not blended into one score.

### Stage 1 — deterministic retrieval (`rank.py`)

- `bucket_score` — hours closed against requirements still outstanding, from Banner attributes.
  Always reliable. A must-include bucket is weighted higher.
- `relevance_score` — TF-IDF cosine between the phrase and title + description + section text.

```
score = bucket_score + 2.0 × relevance + 0.75 when both are non-zero
```

The bonus is what implements **D-19**: a section that closes a requirement **and** fits the
phrase ranks above either alone. Weights are hand-set, not learned.

**Measured, and it does not clear the bar on its own.** TF-IDF is lexical. It ranks *Germanic
Mythology* above *Ancient Philosophy* for `ancient greece`, and matches *Ancient New World
Civilization* on the word "ancient". Normalising relevance per query and deduping helped;
neither fixes synonymy. This is the reason stage 2 exists.

### Stage 2 — reranking (`rank_llm.py`)

TF-IDF retrieves the top 80; the model reorders *those* and writes the `reason` line.

| Env var | Default | Effect |
|---|---|---|
| `NAVIGATOR_RANKER` | `auto` | `auto` reranks when a credential exists, else TF-IDF. `llm` forces. `tfidf` never calls. |
| `NAVIGATOR_MODEL` | `claude-opus-5` | `_supports_effort` omits `effort` and adaptive thinking for Haiku 4.5 and older, which reject them with a 400 |
| `NAVIGATOR_EFFORT` | `medium` | Set for latency, not cost — this is an interactive path |

**The validation boundary is the architecture.** The model is handed real CRNs. Every CRN it
returns is checked against that input set; anything else is discarded (`_validate`) and the
discarded count is surfaced in the UI. A candidate the model omits is appended rather than
lost. This implements FR17–FR19 and is what makes **D-16** a property of the system rather
than a hope about the prompt.

**Only the phrase, the outstanding bucket names, and public catalog text leave the machine.**
No name, no ID, no completed coursework, no grades (**NFR12**). `python test_rank_llm.py` —
14 assertions, no API key required — exercises validation, omission-append, and the fallback.

**Known gap.** The LLM path has never run against a live credential. A fake key proved the
loader, the network path and the fallback, but a 401 is rejected before the body is parsed, so
`output_config.format` and the response schema remain unvalidated. The first real call may
surface a schema error; the fallback will catch it and serve TF-IDF. The sharpest first test is
`ancient philosophy` for student 1 — if reranking moves *Ancient Philosophy* above *Germanic
Mythology* it is earning its cost, and if it does not, that is a finding too.

### Uncertainty handling (D-21, D-27)

926 sections carry Banner's `Special Topics Course` attribute. Flagging all of them is wrong:
all **136** `Legends` sections carry it and are a known First-Year Compass requirement, and 166
of the 926 carry a real gen-ed bucket. So a course is `topic_uncertain` only when it has a
special-topics section **and** its description is missing or reads as the generic rotating
blurb. Such a section still ranks on everything it closes, is never hidden, and carries
"cannot determine the topic — ask your advisor" on the relevance half alone.

> **Open defect.** `ingest.GENERIC_DESC_PATTERNS` under-matches. `\bvaries? (by|with|each) …`
> expands to "varie" or "varies" and therefore never matches "**vary**", and no pattern matches
> "subject matter varies". **14 of 259** special-topics courses carry the generic blurb and are
> not flagged; the count is 72 and should be ~86. They are currently ranked on phrase relevance
> they do not have. The fix must be title-aware — `NEW 490`'s title names its topic even though
> its description does not — which makes it a refinement of D-27 and a team decision, not a
> patch.

The seminar-theme work is the largest of these, because it adds a requirement *kind* the schema
does not yet have: coverage across three themes plus a level distribution, rather than hours
against a bucket pool.

## 8. Cross-cutting

**Logging.** Standard Flask logger. Index construction and every reranker fallback log at
warning with the exception type. `desc_fetch.log` records the description crawl.

**Configuration.** Environment variables with a `.env` loader. `.env` is read with `utf-8-sig`
because PowerShell writes a BOM that otherwise corrupts the first key. Environment variables
do not persist between tool invocations on this machine, which is why the loader exists rather
than relying on the shell.

**Error handling.** One rule: the ranker may never take the page down. Every reranker exception
is caught, logged, and answered with the deterministic ordering.

**Testing.** `test_rank_llm.py`, 14 assertions, no credential needed. Covers the validation
boundary, omission-append, and fallback. There is no test suite for `db.outstanding_buckets`,
which is the highest-risk untested code given NFR8.

## 9. Deliberately not built

| Not built | Reason |
|---|---|
| Auth provider, passwords, sessions | The role split is what matters for the demonstration; the security model is not the subject. Shipping this for real would need it. |
| Deployment, hosting, CI | Out of scope for a course prototype |
| `prerequisite` and `instructor` as entities | No finding asks for them |
| Any approval workflow | No formal approval exists before the third-year review (**D-26**) |
| Multi-term planning | One term is the demonstrated unit of work |
| A topic or career taxonomy | **D-22** forbids it — depth study is not a fixed record |

The first row is the one to be honest about in the final presentation: the product models two
roles and authenticates neither.
